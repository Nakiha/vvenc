# Packed byte input for the live path

`VVENC_LIVE_INPUT8_VERSION=1` extends `vvencYUVBuffer` and requires all clients to rebuild against the matching fork ABI. It adds three non-owning, read-only `planes8` pointers. Plane width/height and stride remain in `planes`; stride is bytes when byte input is selected. All active byte planes must be present and every corresponding legacy `planes[].ptr` must be null. Default initialization clears the new pointers and trace flag. Buffer free functions never free byte pointers.

The API accepts packed input only for the verified serial LiveCqfPoll path with input and internal precision 8. Invalid dimensions, short/negative strides, missing chroma, mixed pointers and incompatible modes fail before reading samples. The library copies active rows into its owned working pixels before returning; callers need no extra full-frame 16-bit staging allocation. Input pixels are not modified. Existing row/bottom padding stays in the copy owner. The legacy downsample branch is explicitly unavailable for byte input.

This is an input contract, not a complete byte-storage encoder. Byte input still zero-extends into owned working storage. Optional `LiveNative8Ref=1` now creates separate byte reference planes and runs unweighted uni-direction integer motion estimation against byte original blocks with scalar/SSE/AVX2 SAD. It requires serial live CQF, internal 8-bit and MaxParallelFrames=0. Internal IFP line scheduling may remain enabled, but EncGOP owns exactly one picture encoder and returns it only after packing/publication. The original reconstruction remains available for fractional interpolation and other working paths. This currently adds a byte reference cache; it does not remove the wide reconstruction allocation. `Sample8` is unsigned byte storage, `Residual` is signed 16-bit, and `WorkingSample` retains the legacy signed intermediate precision. Coefficients remain 32-bit. Residual buffer APIs use explicit residual names. Do not change the global working Pel typedef to uint8_t.

PTS, ordinary-I requests, per-picture QP offsets, pending poll and tracing use the existing picture ownership. There are no new queues, future-picture reads or IPC frame pointers. JSON support for one-pass lookahead RC is unchanged.

The parent service has a read-only mmap/API fixture comparing byte input with equivalent legacy 8-bit samples in 16-bit containers, invalid-input checks and live HEVC integration/EOF and on/off trace equivalence checks.

Byte references are packed once after finalizePicture and the existing CTU/filter/border completion barrier, before publishing isReconstructed. They are immutable until Picture reuse. Reset invalidates readiness, destroy releases storage. A missing/unready byte reference in the enabled path fails explicitly; it does not silently use the wide path. Reference stride is bytes with the same numerical stride as wide reference samples, including margins. This permits candidate coordinate translation without aliasing byte storage as signed residuals. Weighted/bi search, fractional/HAD/DMVR/IBC and >8-bit paths retain their original kernels. SAD preserves bounded early termination for large blocks; any partial result is strictly above the current best bound. Costs of competitive candidates remain exact (no candidate decision or search-range change). SIMD handles tails without overreading and uses 64-bit accumulation.

Trace ABI version 3 adds `byte_me_blocks` (actual byte search blocks, opt-in relaxed atomic accounting) and `byte_reference_pack_us` (wall time within finalization). Trace-off has no per-block atomic increments or packing clocks. Diagnostic codec tracing remains outside formal performance A/B runs. Parent tests verify pixel margins/lifecycle, scalar/SSE/AVX2 exact costs and guard pages, and bit-exact payload/CTS relative to the legacy reference path with forced-I short groups and EOF.

For single-thread phase telemetry, wall start precedes CPU start and CPU end precedes wall end. This encloses clock-read overhead and preemption between reads; do not end the wall interval before taking CPU end. Parallel CTU CPU sums remain overlapping costs, not elapsed latency.

Trace ABI v4 appends an opt-in worker CPU ledger after the complete v3 field prefix (including both byte-input fields). The service requires the matching v4 SDK before reading it. `VVENC_LIVE_CPU_LEDGER=1` enables fixed per-worker CPU-clock slots; disabled runs retain branch and task-kind bookkeeping overhead and must not be called zero-cost. Pool scan/yield/lock/task categories are disjoint within worker publications, while MCTF and CTU are subsets of task CPU. Snapshots have bounded retries and can be marked invalid. Process, caller and worker publications have no synchronized common CPU window, so their signed residual is not precise component attribution.
